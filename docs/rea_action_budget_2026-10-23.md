## 已实施的数据流

**已确认（源码）**：

```text
GameState.forces[].action_points
 → boundary: 仅己方 VisibleGameState.forces
 → own city.force_id → 对应军团余额（不累计其他军团、不按城市复制余额）
rules.action_points_cost                         基础标价
rules.effective_action_points_cost              已核实有效费用，默认unknown
 → enumerate_legal_actions / _check_action_points
   ├─ 已知余额 < 已知有效费用：排除该单条动作
   ├─ 费用未知：标记action_points_cost
   └─ 余额缺失/未知/重复ID：标记action_points_balance
 → patrol仍带patrol_preconditions → 后续战术层／执行器
```

`ActionRuleSpec.effective_action_points_cost`为新增可选RuleValue；加载器拒绝已知负数、布尔、浮点和字符串费用。生产规则目前只有巡察=20，其他动作默认未知，不能以基础标价替代。仅用于已验证固定成本，未来按城市/人员变化的有效费用需要从可见状态逐动作解析，不能向这一个常量字段填入不带条件的“半价”。

**已确认**：每条候选独立判断，不消耗、不预留输入状态中的余额。同军团有20点时，A城巡察与B城巡察可以同时列为互斥备选，不能解释为两条都能执行。`StrategyLoop.run_one_turn()`仍使用一次快照执行一批选择，真实执行器尚不存在；本轮没有解决整批预算调度。

**已确认（只读生产验收）**：当前旬1、己方军团0余额90，巡察有效费用20，15个单人巡察备选均通过余额检查、仍带 `patrol_preconditions`。最终证据为 `production_budget_readback_with_eligibility_marker.json`；较早的 `production_budget_readback.json`保留为补标记前的历史输出，不作为完整合法性证明。未发送任何候选到游戏。

**已确认（离线验收）**：新增18项测试，共384项通过。覆盖0/19/20/35余额、治安99/100、基础费用不冒充有效费用、同势力不同军团、缺失/未知/敌方/重复ID余额、同军团多城作为备选且不改状态、有效费用类型校验。余额19/20和治安99/100是合成测试，尚未在真实游戏制造这些边界。

## 前置条件、风险与验证方式

- **已确认的版本依赖**：本轮由verified_image和桥接器在读取前校验目标，另比较选定运行时代码。**待验证／未实现**：规则加载器和RealGameStateSource没有新增自动指纹门禁，不能宣称它们独立拒绝所有不匹配构建。接真实执行前应将身份、代码及结构检查固化到启动路径。
- **待验证的规则覆盖**：巡察成本固定不代表其他动作无折扣，也不保证完整人员资格。验证方式为匹配版本的具体命令、UI确认费用、扣减及反例，而不是搬用相似函数地址。
- **已确认的实验边界**：上轮只授权并执行一次巡察和一次旬，本轮没有扩大游戏操作；槽5恢复点保留。后续动态对照须在可恢复状态、明确实验范围内进行，不以无界重试代替验收。
- **已确认的快照局限**：双读一致不等于跨表原子快照。待验证方案是在稳定玩家阶段读状态，核对日期/阶段未变化，执行前重新检查余额和对象身份。
