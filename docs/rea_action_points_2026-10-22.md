## 开发目的与当前实现

- **已确认（仓库 README、`boundary.py`、`strategy_loop.py`）**：项目研究让 LLM 基于人类可见局势作高层决策，由规则战术层选动作、执行层通过键鼠操作游戏，并用对局观察 AI 与人的决策差异。中间件承担读取、信息过滤、动作约束和执行反馈；并非让模型直接访问完整游戏内存。
- **已确认（`perception.py`、`boundary.py`、`strategy_loop.py`）**：`RealGameStateSource.read()` 已复用 `parse_game_state()` → `filter_game_state()`。战略备忘录、局势摘要、意图解析、战术选择和假执行器已有离线链路。当前 `StrategyLLM` 只有假后端；不等于已接入真实模型。
- **已确认（`strategy_loop.py`、`menu_execution.py`、offsets）**：真实 `ActionExecutor` 尚未接入主循环，`RealGameStateSource.advance_turn()` 仍抛 `NotImplementedError`；菜单执行脚手架存在，但地图定位、选择对象、阶段/控制权识别仍有 unknown。单次手工辅助 UI 实验不等于生产自动闭环。
- **已确认（`legal_actions.py`、`domestic_rules.py`）**：规则中 unknown 条件被记录在 `unverified_constraints`，并不全部阻止候选生成；`action_points_cost` 已有模型字段，但余额约束尚未执行。因此不能把全部候选称为已验证可执行动作。
- **已确认（`strategy_loop.py::run_one_turn`）**：当前先读一次状态、枚举并选择整批动作，再逐条执行；每次调用从空的已指派集合开始。尚未按每次真实动作的结果刷新资源和人员状态。
- **信息缺口／待验证**：README 提到的完整规格/wiki未在仓库收录，无法确认全部验收细则；真实可见性自动来源、多人选将模型、通用成本修正、恢复规则、地图投影和可重入执行协议均未完成验证。生产信息边界的实现存在，不等于所有可见性规则都已与游戏逐项对照。

## 已接入的数据流与验证

**已确认（当前源码）**：

```text
匹配版本、解析动态锚点
  → offsets/pk_1.1_cn.json: force[47], +0x2C u8
  → perception.parse_forces() → GameState.forces[].action_points
  → boundary.filter_game_state(): 仅保留己方军团
  → VisibleGameState.forces[]: VisibleForce(index, faction_id, action_points)
  → RealGameStateSource.read()
  → summarize_situation(): own_force_action_points
  → render_situation_text() → build_strategy_prompt() → StrategyLLM.decide()
```

未知余额为 `None`，摘要显示“未知”；不伪造0。摘要按军团列出一次，不按城池累计同一余额。敌方及无归属军团余额不进入可见态。来源：`game_state.py`、`perception.py`、`visible_state.py`、`boundary.py`、`situation_summary.py`。

**已确认（实机读取）**：`rea/2026-10-22/production_readback.json` 记录生产 `RealGameStateSource.read()` → 过滤 → 摘要，当前旬1、己方军团0余额90。这验证的是读取链，不是模型调用或自动执行。

**已确认（离线测试）**：新增 `tests/test_force_action_points.py` 覆盖u8读取、相邻字节隔离、旧配置保持未知、47槽边界、己方过滤、摘要按军团输出和未知值。完整测试356项通过。离线测试不替代上面的动态覆盖缺口。

## 关键风险与可验证方式

- **已确认的版本依赖**：运行时与磁盘代码不同，历史地址可能不适用。每次研究先校验EXE指纹、架构、模块基址、动态锚点；新载体记录完整来源。漂移即不沿用字段语义。
- **待验证的语义外推**：一个军团的一次巡察不能涵盖所有成本、特殊军团和恢复规则。按上表补对照，不用猜测结果填生产配置。
- **已确认的快照局限**：探针连续两读相同只证明所读范围当时稳定，不是跨表原子快照。待验证方案：执行前后核对日期/阶段，变动时丢弃快照并重读。
- **已确认的范围边界**：本次仅执行用户批准的一次巡察和一旬，保留槽5恢复点；未以写内存、注入、调用内部函数代替键鼠。后续未覆盖的游戏实验需基于可恢复状态安排，不能用自动重试扩张实验次数。
- **待验证的控制权信号**：日期递增不等于玩家已恢复控制。验收须同时观察UI事件结束及可操作状态，之后才能发布真实 `advance_turn()`。
